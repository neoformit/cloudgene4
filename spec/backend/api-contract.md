# Backend API contract

## Purpose

This file is the backend index of the HTTP contract between the Vue SPA and the Django/DRF
backend (constitution Article 5). The contract itself is the OpenAPI 3.0.3 document
`schema.yaml` at the repository root, generated by drf-spectacular from the DRF serializers and
views. This file states how that document is produced and checked, the conventions every `/api/`
operation follows (base path, slashes, auth, error envelope, pagination, formats, content types),
and lists every operation by `operationId` with its owning spec file. Field-level shapes live in
`schema.yaml` only; this file names components, it does not copy them.

## Scope

Covered:

- `schema.yaml` (the contract), `cloudgene_django/settings.py` (`REST_FRAMEWORK`,
  `SPECTACULAR_SETTINGS`, middleware order), `cloudgene_django/urls.py` and each app's `urls.py`
  (routing).
- `core/exceptions.py` (error envelope), `core/serializers.py` (`Error` component and the
  `add_error_envelope` schema hook, `MessageSerializer`), `core/middleware.py` (trailing slash,
  JSON body limit), `core/pagination.py`, `core/permissions.py` (`IsAdmin`), `core/views.py`
  (`api_not_found`, `csrf_failure`).
- Contract-level tests: `core/tests/test_schema.py`, `accounts/test_contracts.py`,
  `workflows/test_contracts.py`, and the envelope/auth/routing tests in `core/tests/test_api.py`.

Out of scope (owned elsewhere):

- What each operation does and its business rules: the owning file named in the catalogue.
- The frontend side of the contract (API modules, fixtures, schema-loaded contract tests):
  [frontend/api-contract.md](../frontend/api-contract.md).
- Login, lockout and token lifecycle: [authentication.md](authentication.md), [accounts.md](accounts.md).
- Group-based workflow access and the admin definition in detail: [access-control.md](access-control.md).
- `/django-admin/` (Django admin site) and the SPA catch-all route: [overview.md](overview.md).

## Dependencies

- [authentication.md](authentication.md) — session/CSRF and token auth mechanics.
- [access-control.md](access-control.md) — `is_admin` and per-workflow group access.

## Requirements

### Contract mechanism

- **BE-API-001** `schema.yaml` at the repository root MUST be the only definition of the
  `/api/` interface. It MUST be generated by drf-spectacular with
  `python manage.py spectacular --file schema.yaml --validate` and committed.
- **BE-API-002** The backend test suite MUST fail when the committed `schema.yaml` differs
  byte-for-byte from a freshly generated one, and the failure message MUST print the regenerate
  command.
- **BE-API-003** Every operation reachable under `/api/` that the SPA or an API client may call
  MUST appear in `schema.yaml` with an `operationId`, and MUST be listed in the
  [operation catalogue](#operation-catalogue) of this file. Exempt: `/api/schema/` and
  `/api/schema/swagger-ui/` (documentation endpoints).
- **BE-API-004** Every operation MUST declare an explicit request serializer (when it takes a
  body) and an explicit response serializer or typed media response in `schema.yaml`. A response
  component MUST NOT contain untyped (`{}`) or free-form object fields unless this file lists them
  as accepted exceptions.
- **BE-API-005** `operationId`s MUST be stable. Renaming or removing one is an interface change
  and MUST follow the [change procedure](#change-procedure). New operations SHOULD pin their
  `operationId` with `extend_schema(operation_id=...)`.
- **BE-API-006** Backend contract tests MUST validate real responses (success and error paths)
  against the `schema.yaml` component documented for that operation and status. (planned)
- **BE-API-007** `schema.yaml` SHOULD list, per operation, each non-2xx status the view can
  return (not only `default`), so that status codes can be quoted from it (Article 5.3). (planned)
- **BE-API-008** A response field that the view can return as `null` MUST be declared
  `nullable: true` in `schema.yaml`, and a field declared non-nullable MUST never be `null` in a
  real response. (planned) The SPA's contract fixtures rely on this
  ([../frontend/job-detail.md](../frontend/job-detail.md) FE-JDET-023).

### Routing

- **BE-API-010** All operations MUST live under the base path `/api/`. Canonical paths end with
  `/` as written in `schema.yaml`.
- **BE-API-011** A request to `/api/<path>` without the trailing slash MUST be served by the
  operation at `/api/<path>/` when only the slashed form resolves. The request MUST be routed
  internally (no redirect), so method, headers and body are preserved.
- **BE-API-012** A request to an unknown path under `/api` (including `/api` itself) MUST return
  `404` with the error envelope, `code` `not_found`, message `Not found.`. It MUST NOT return the
  SPA HTML.
- **BE-API-013** A known path called with a method it does not support MUST return `405` with the
  error envelope, `code` `method_not_allowed`.

### Error envelope

- **BE-API-020** Every non-2xx JSON response from an `/api/` operation MUST use the `Error`
  component of `schema.yaml`:

  ```json
  {"error": {"message": "<string>", "code": "<string>", "fields": {"<field>": ["<string>", ...]}}}
  ```

  `message`, `code` and `fields` MUST always be present; `fields` is `{}` when the error is not
  tied to input fields. The one exception is `health` (BE-API-028).
- **BE-API-021** A validation failure MUST return `400` with `code` `invalid`. `fields` MUST map
  each failing field to its messages; nested fields use dotted keys (`nested.a`) and list items
  use `[i]` (`navbar[0].url`). `message` MUST be the first non-field message if any
  (`non_field_errors`, `detail`, `__all__` keys are moved out of `fields`), else
  `"<field>: <first message>"`.
- **BE-API-022** An unhandled exception MUST return `500` with `code` `server_error` and message
  `Internal server error.`; the traceback is logged to `cloudgene.api` and MUST NOT appear in the
  response.
- **BE-API-023** Oversized requests MUST return `413` with `code` `upload_too_large`: a
  non-multipart `/api/` body whose `Content-Length` exceeds `API_JSON_BODY_MAX_MB` (default 10)
  MiB is rejected before the body is read; Django's `RequestDataTooBig`, `TooManyFilesSent` and
  `TooManyFieldsSent` are mapped to the same code. Other `SuspiciousOperation` errors MUST return
  `400` `invalid`.
- **BE-API-024** Error `code` values MUST come from the [error code table](#error-codes). A view
  that needs a new code MUST add it to that table in the same change.

### Authentication and authorisation

- **BE-API-030** The API MUST accept two schemes, as declared in `components.securitySchemes`:
  `cookieAuth` (Django session cookie `sessionid`) and `tokenAuth` (header
  `Authorization: Token <key>`). Token authentication is tried first.
- **BE-API-031** Session-authenticated unsafe requests (`POST`, `PUT`, `PATCH`, `DELETE`) MUST
  carry the `X-CSRFToken` header matching the `csrftoken` cookie, else `403` `csrf_failed`.
  `auth_login_create` MUST enforce CSRF even for anonymous callers. Token-authenticated requests
  MUST NOT require CSRF.
- **BE-API-032** An anonymous call to an operation that requires a user MUST return `401` with
  `code` `not_authenticated` and a `WWW-Authenticate: Token` header. An invalid token MUST return
  `401` `authentication_failed`.
- **BE-API-033** A non-admin user calling an admin operation (every path under `/api/admin/`)
  MUST receive `403` `permission_denied` and nothing MUST change. Admin means superuser, or
  `is_staff`, or member of the group `admin` (`core/permissions.py`).
- **BE-API-034** Owner-scoped operations (`jobs_retrieve`, `jobs_status_retrieve`,
  `jobs_cancel_create`, `jobs_destroy`, `jobs_log_retrieve`, `jobs_outputs_retrieve`) MUST return
  `404` `not_found` to an authenticated user who is neither the owner nor an admin, so the
  existence of other users' jobs is not revealed.
- **BE-API-035** Every operation MUST enforce the "Auth" column of the catalogue: `anonymous` = no
  authentication needed (a user may still be authenticated, which can change the result);
  `user` = any authenticated active user; `owner` = owning user or admin; `admin` = admin only.

### Pagination

- **BE-API-040** Operations whose 200 response is a `Paginated*List` component MUST return
  `{"count", "next", "previous", "results"}`, accept `?page=` (1-based) and `?page_size=`,
  default to 20 items per page, and cap `page_size` at 200. A page number past the end MUST return
  `404` `not_found`.
- **BE-API-041** `admin_groups_list`, `admin_pages_list`, `admin_workflows_list` and
  `admin_workflows_sync` MUST return a plain JSON array (not paginated), as `schema.yaml` states.

### Formats and content types

- **BE-API-050** Timestamps MUST be ISO 8601 strings in UTC (`format: date-time`); the server
  runs with `USE_TZ = True`, `TIME_ZONE = 'UTC'`. Nullable timestamps are `null`, never `""`.
- **BE-API-051** Identifiers MUST use these formats: jobs — UUID string (`format: uuid`; path
  parameter accepts `^[0-9a-fA-F-]{32,36}$`); users, groups, categories, job steps, job messages,
  job outputs, system logs — integers; workflows — the string id from `cloudgene.yaml`; pages — a
  slug of `a-z`, `0-9`, `-`, `_`, at most 64 characters.
- **BE-API-052** Request bodies MUST be accepted in each media type `schema.yaml` lists for the
  operation (`application/json`, `application/x-www-form-urlencoded`, `multipart/form-data`). The
  SPA sends JSON except for `jobs_create`, which it sends as `multipart/form-data` so it can carry
  files.
- **BE-API-053** JSON responses MUST use `application/json`. `jobs_log_retrieve` MUST return
  `text/plain; charset=utf-8`. `jobs_outputs_retrieve` MUST return the file body with
  `Content-Disposition`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox`
  (content-type and inline rules: [jobs-api.md](jobs-api.md)). Errors from these two operations
  MUST still use the JSON error envelope.

### Health

- **BE-API-028** `health` MUST answer without authentication (it ignores any credentials) and
  MUST return the `Health` body both with `200` (database reachable) and with `503` (database
  unreachable). `schema.yaml` MUST document the `503` response. (Detail:
  [server-pages-mail.md](server-pages-mail.md).)

### Change procedure

- **BE-API-060** Every interface change MUST follow the [change procedure](#change-procedure) in
  one change set.

### Security schemes (quoted from `schema.yaml`)

```yaml
cookieAuth: {type: apiKey, in: cookie, name: sessionid}
tokenAuth:  {type: apiKey, in: header, name: Authorization,
             description: Token-based authentication with required prefix "Token"}
```

Operations open to anonymous callers list `security: [{tokenAuth: []}, {cookieAuth: []}, {}]`;
`health` lists only `[{}]`; all others list `tokenAuth` and `cookieAuth`. The schema does not
distinguish `admin` from `user`; the catalogue below does.

### Cookies and headers

| Name | Kind | Set by | Used for |
|------|------|--------|----------|
| `sessionid` | cookie, HttpOnly, SameSite=Lax | `auth_login_create` | Session auth |
| `csrftoken` | cookie, readable by JS, SameSite=Lax | Any SPA page (`spa_index`), `auth_me_retrieve`; rotated on login | Source of `X-CSRFToken` |
| `X-CSRFToken` | request header | SPA | CSRF check on unsafe session requests |
| `Authorization: Token <key>` | request header | API clients; key from `me_token_create` | Token auth (no CSRF) |
| `WWW-Authenticate: Token` | response header | 401 responses | — |
| `Retry-After` | response header | `auth_login_create` 429 `account_locked` | Seconds until unlock |

`Secure` is added to both cookies when `DJANGO_SECURE_COOKIES=1`.

## Behaviour

### Request pipeline (contract-relevant order)

`cloudgene_django/settings.py` `MIDDLEWARE`: `SecurityMiddleware` → `WhiteNoiseMiddleware` →
`ApiTrailingSlashMiddleware` → `JsonBodySizeLimitMiddleware` → sessions → `CommonMiddleware` →
`CsrfViewMiddleware` → auth → `WorkflowSyncMiddleware` → ….

1. `ApiTrailingSlashMiddleware`: for `/api/...` paths without a final `/`, if the path does not
   resolve (or resolves only to the `api-not-found` catch-all) and `path + '/'` does, rewrite
   `path_info` and `path` in place. No redirect.
2. `JsonBodySizeLimitMiddleware`: for `/api/` requests whose content type is not
   `multipart/form-data`, reject `Content-Length > API_JSON_BODY_MAX_MB` MiB with a `413` envelope.
3. URL resolution: app URLconfs first; then `^api(/.*)?$` → `core.views.api_not_found` (404
   envelope); then the SPA catch-all.
4. DRF view: `TokenAuthentication`, then `SessionAuthentication` (CSRF on unsafe methods);
   default permission `IsAuthenticated`; default pagination `core.pagination.StandardPagination`;
   exceptions go to `core.exceptions.api_exception_handler`.

### Exception mapping (`core/exceptions.py:api_exception_handler`)

| Exception | Result |
|-----------|--------|
| `Http404` | `NotFound` → 404 `not_found` |
| Django `PermissionDenied` | DRF `PermissionDenied` → 403 `permission_denied` |
| `TooManyFilesSent`, `TooManyFieldsSent` | 413 `upload_too_large`, message `Too many files were included in this request.` |
| `RequestDataTooBig` | 413 `upload_too_large`, message `The request is too large.` |
| other `SuspiciousOperation` | 400 `invalid` |
| DRF `ValidationError` | 400 envelope per BE-API-021 |
| other DRF exception with dict/list detail | envelope with flattened `fields`, `code` = exception default code |
| other DRF exception | `code` = detail code or default code; `PermissionDenied` whose message starts `CSRF Failed` → `csrf_failed` |
| anything else | 500 `server_error` (logged) |

Views also build envelopes directly with `error_response(message, code, status, fields)`;
non-DRF views use `json_error`. Django's CSRF middleware failure view (`core.views.csrf_failure`)
returns the 403 `csrf_failed` envelope for `/api/` paths and plain text elsewhere.

### Change procedure

Article 5.1b, as a checklist. All steps land in one change set.

1. Change the backend serializer and view. Use an explicit serializer for request and response;
   pin a new `operationId` with `extend_schema(operation_id=...)`.
2. Regenerate the contract: `python manage.py spectacular --file schema.yaml --validate`. Fix
   every warning.
3. Run `python manage.py test core.tests.test_schema` (staleness) and the backend tests of the
   changed area; add or update a contract test that validates the new response against the
   `schema.yaml` component, including the error path.
4. Update the frontend API module (`frontend/src/api/*.js`), its fixtures and the views/stores
   that use it; frontend contract tests must load the component from `schema.yaml`.
5. Update this file: the catalogue row (operationId, method, path, auth, request, success,
   errors, owner), the component index, and the error-code table if a new code was added.
6. Update [frontend/api-contract.md](../frontend/api-contract.md) with the same operationId.
7. Update the owning spec file's requirements and acceptance tests.
8. Run `scripts/test.sh unit` (Django checks, migrations check, Django tests incl. staleness,
   vitest) and the e2e tests that cover the operation.

## Open questions

1. Should `health` keep returning its own body on `503` (useful for load balancers), or use the
   error envelope? This file assumes the former and asks only that the schema document it.
2. Should error responses be listed per operation in `schema.yaml` (BE-API-007) by extending
   `add_error_envelope` with a per-view map, or by `extend_schema(responses=...)` on each view?
3. Is `/api/schema/` meant to be public in production? It is served with drf-spectacular's
   default `AllowAny`.
4. Should `admin_jobs_list` and `jobs_list` remain separate for admins (an admin's `jobs_list`
   shows only their own jobs, while `jobs_retrieve` lets them open anyone's)?
